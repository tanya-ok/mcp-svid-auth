# Configuration reference

All commands are installed by `uv sync` as console scripts. `--socket` defaults to the `SPIFFE_ENDPOINT_SOCKET` environment variable.

The flag tables, fixed values, policy schema and revocation file schema below are generated from the code by `scripts/gen_config_docs.py`. CI fails if they drift. How to combine the production flags is in [operations](operations.md).

| Environment variable | Read by | Meaning |
|---|---|---|
| `SPIFFE_ENDPOINT_SOCKET` | all commands that fetch SVIDs or bundles | Default Workload API socket |
| `HOSTNAME` | `mcp-svid-authz`, `mcp-svid-notes` | Default `--audit-replica-id` |
| `MCP_ACCESS_TOKEN_FILE`, `MCP_ACCESS_TOKEN` | set by `mcp-svid-stdio` for its child | Token file path; the token itself only with `--export-token-env` |

## Policy file

Example from `deploy/policy.yaml`:

```yaml
# Which SPIFFE IDs may get access tokens for which MCP servers, with which scopes.
# Anything not listed is denied.
trust_domain: example.org
clients:
  - spiffe_id: spiffe://example.org/agent/research
    resources:
      http://notes-a:8101/mcp: [notes:read, notes:write]
      http://notes-b:8102/mcp: [notes:read]
  # notes-a calls notes-b with its own token for notes.search_upstream.
  - spiffe_id: spiffe://example.org/mcp/notes-a
    resources:
      http://notes-b:8102/mcp: [notes:read]
# spiffe://example.org/agent/intruder has a valid SVID but is deliberately not listed.
```

| Key | Type | Meaning |
|---|---|---|
| `trust_domain` | string, required | Only SVIDs from this trust domain are accepted |
| `clients` | list | One entry per SPIFFE ID |
| `clients[].spiffe_id` | string, required | Exact SPIFFE ID (SVID `sub`) |
| `clients[].resources` | map | Resource URI to list of allowed scopes. Trailing slashes are ignored when matching. |

## Revocation file

Read by `--revocation-file` on the token endpoint and MCP server. Unknown keys, a file over 1048576 bytes or more than 100000 entries make every check fail closed.

| `revoked_jti` | list of strings | Access token `jti` values refused before their `exp` |
| `blocked_spiffe_ids` | list of strings | SPIFFE IDs refused as token subject, client or actor, and refused new tokens |

## Behaviour notes

- `mcp-svid-agent` calls `notes.search` then `notes.write`. It exits with code 2 and prints a `token_denied` event when the token request fails. With `--token-per-call` it fetches a new SVID and token before each call after the first.
- `mcp-svid-authz` refuses to start without exactly one key source: `--signing-key-file`, `--transit-address`, or `--dev-ephemeral-signing-key`. Persistent sources need `--signing-rotation-seconds 0`.
- `mcp-svid-stdio` is described in [stdio wrapper](stdio-wrapper.md).

## Policy decisions

The policy is an allowlist of which SPIFFE IDs may get access tokens for which MCP servers, with which scopes. Anything not listed is denied.

Decision order:

| Condition | Error |
|---|---|
| SPIFFE ID not listed | `unauthorized_client` |
| Resource not listed for that ID | `invalid_target` |
| Requested scopes not a subset of the listed scopes | `invalid_scope` |

The token carries exactly the requested scopes, not the full grant.
